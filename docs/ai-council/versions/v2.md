## 第2部 — AI 利用の前提・禁止領域・データ分類

### 2.1 【結論】

- 弁護士法 23 条と各国守秘規律の下では、依頼者情報の外部 LLM 送信は原則禁止。例外条件は §2.7。
- **データ分類 D/C/B/A** を最上位ルールとし、ツール選定・運用・監査はすべてこの分類に従属する。
- 越境移転（PIPL/APPI/US 州法）と弁護士・依頼者間秘匿特権（A-C privilege / work product）は、入力時点で考慮する。

### 2.2 AI 常用前提の問い直し

- 「AI を使うのが当たり前」を前提にしない。**機密案件では AI を使わない方が正解**である工程が存在する [GPT R2 §1.1 / Perp R1 §1]。
- AI 利用は工数効率や品質向上のための選択肢であり、義務ではない。

### 2.3 業務類型別 AI 利用可否

| 業務類型 | AI 利用 | 主担当 AI | 補助・検証 |
|---|---|---|---|
| CMP 戦略立案・依頼者対応 | **不可** | — | 人間専門家のみ |
| CMP 関連の依頼者向け書面起案 | **不可（本文は AI 投入禁止）** | — | 抽象化済み論点のみ B-class で可 |
| 抽象化した法律論点の調査 | 可 | Perplexity (Computer) / Gemini Deep Research | Claude による cross-check |
| 越境法令・最新規則の確認 | 可（ただし要再確認） | Perplexity | Gemini Deep Research、§10 別紙 D で trace |
| OSINT（公開情報のみ） | 可（§5.y SOP 必須） | Perplexity / Cascade | — |
| コード（GitHub Pages / 個人 repo） | 可 | Cascade / Claude Code | VS Code Audit profile で merge 前確認 |
| 文書整形・翻訳（B/A class） | 可 | Claude Code / Cascade | — |
| 文書整形・翻訳（D/C class） | **不可** | — | — |

### 2.4 データ分類体系 D/C/B/A [GPT R2 §1.1 / Perp R1 §1]

| 区分 | 内容 | AI 入力可否 | 例 |
|---|---|---|---|
| **D-class / Privileged** | CMP 本文、依頼者氏名、案件番号、訴訟戦略、相談記録、A-C privileged communications | **外部 AI 全面禁止** | 委任契約書、戦略メモ、依頼者から受領した CMP 本体 |
| **C-class / Sensitive** | 匿名化前の下書き、相手方氏名、時系列、内部メモ、識別情報を含む証拠物 | **原則禁止**。匿名化＋人間承認後に B 降格可 | 起案中の準備書面、和解案下書き |
| **B-class / Controlled** | 匿名化済み抜粋、抽象化済み論点、整理済み公開情報 | **条件付き可** | 「中国会社法 X 条の解釈論点」のような抽象論 |
| **A-class / Public** | 公開 Web、GitHub Pages、公開資料、立法資料 | **可** | 政府発表、判例 DB、商業出版書籍 |

**分類不能な対象は、より高い機密分類として扱う**（fail-safe）[GPT R2 §1.1]。

### 2.5 越境データ移転の扱い [Perp R2 §3.1]

- **中国側**: PIPL 38〜43 条系の越境移転、標準契約 (CN SCC)、安全評価（CAC）。
- **日本側**: APPI 28 条（外国第三者提供）と本人同意・基準適合体制。
- **米国側**: 州法（CCPA/CPRA）、契約上の DPA、各州弁護士会の AI 倫理オピニオン。
- **帰結**: 外部 AI ベンダーへの入力は技術設定の問題ではなく、**越境移転レイヤーの問題**。各 AI のリージョン・データ処理地・サブプロセッサ開示は §10 別紙 C で四半期毎に確認 [要再確認]。

### 2.6 特権・work product と AI 入力 [Perp R2 §3.2]

- 米国法上、第三者（外部 AI ベンダー）への開示は privilege waiver と評価される余地（Kovel 類推、common interest の限界）。
- 日本側の弁護士秘匿特権（限定的）と職務基本規程上の守秘との関係。
- **帰結**: 「契約上 retention=0 / training=off」だけでは privilege 維持の十分条件にならない。本書は privilege waiver リスクを D/C class 入力禁止の根拠の 1 つとして明示する。具体的判断は §6 人間専門家に委ねる。

### 2.7 AI 利用許容条件（C/B class の境界判断）

C-class を B-class に降格して AI 投入できる条件:
1. 識別情報（依頼者氏名・案件番号・特定可能な日付・場所）をすべて除去
2. 抽象化済みの論点単独で意味が通る
3. 元 C-class 文書との照合が AI 側で不可能
4. 依頼者から事前同意（明示または黙示の継続的合意）取得済み
5. 監査ログに記録（§5 audit log schema）

これら 5 条件を **すべて満たす場合のみ** B 扱い。ひとつでも欠ければ C のまま。

### 4.3 Vault A / B 分離運用（独立節） [GPT R2 §1.3]

| 項目 | Vault A（機密） | Vault B（非機密） |
|---|---|---|

| Vault A → B コピー | **人間承認制**（自動転送禁止） | — |
| 添付ファイル / PDF / 画像 | 混入監査（D-class 含む可能性） | — |
| Spotlight / plugin cache / index | 切り分け検討 | — |
| Community plugin | 通信先・保存先確認後のみ | 同左 |

### 4.4 自律エージェントの権限境界 [Perp R2 §3.5 / Casc 1.3]

Cascade、Devin、Claude Code（agent モード）等の自律エージェントには、操作種別ごとに別 allowlist を持つ:

| 操作種別 | 人間承認前に実行可 | 承認必須 |
|---|---|---|
| shell 実行 | 読み取り系（`ls`、`git status`、`grep`） | 書き込み系（`rm`、`mv`）、外部 API 呼出 |
| ファイル書込 | repo 内 / Vault B 内 | repo 外、Vault A 内 |
| git push | feature branch | main、release |
| ブラウザ操作 | 読み取り、フォーム送信なし | フォーム送信、認証画面 |
| 外部 API 呼出 | 公開 API（OSINT） | 認証付き API、課金 API |
| secret 環境変数参照 | **不可**（常に承認必須） | — |

各エージェントの実装:
- **Cascade**: `.windsurf/rules/` に SafeToAutoRun 基準を静的定義 [Casc 1.3]
- **Claude Code**: agent モード使用時は CLAUDE.md (= AGENTS.md symlink) で同等規律
- **Devin（採用時）**: `ai_policy/devin_allowlist.md` で repo / command / network の 3 層 allowlist [v1 §2.3]

### 5.1 【結論】

- ログ保管先: Vault A 外、`docs/audit-log/<YYYY-MM>.md`（private repo）。
- ログ項目: 日時、AI サービス、操作種別、入力データ class（D/C/B/A）、出力先、人間承認の有無、incident-link。
- **ログ完全性 (tamper-evidence)** [Perp R2 §3.3]:
  - append-only ファイル + 月次 SHA256 ハッシュチェーン
  - 取調べ・懲戒・訴訟時の提出可能性を考慮し、**ログ自体に依頼者識別情報を含めない**

### 5.4 AI 出力物管理 [GPT R2 §1.2 / Perp R2 §1]

- AI 出力は**草案・補助資料**にすぎない。
- 対外提出前、依頼者提示前、裁判所提出前は **人間レビュー必須**。
- AI 出力に含まれる **架空引用・誤法令・誤判例・誤った事実推認** を検査。
- AI 出力の保存先はデータ分類に従う（Vault B が原則、Vault A 取込みは人間承認制）。
- AI 出力が外部 AI 由来である旨と確認状況をログ記載。

### 5.5 AI 生成物の権利・依頼者納品時の表記 [Perp R2 §3.6 / Claude coord §2 Q4]

- ベンダー利用規約上の生成物権利（米英法系・日中法系で扱いが異なる）[要再確認]

### 5.6 インシデント対応 SOP [GPT R2 §1.5 / Perp R2 §2.5]

| 事故類型 | 初動 |
